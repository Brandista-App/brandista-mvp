# B0.14 Frontend API Contract

This documents controllers and DTOs in the current B0.13 source tree, cross-checked against the README. No OpenAPI generator or specification is present. Reconfirm against the SRS when available.

## Connection and authentication

- Local base URL: `http://localhost:8080`; API version prefix: `/api/v1`.
- Compose host ports default to backend `8080` and MySQL `3307`; backend connects to MySQL by Compose service hostname `mysql:3306`.
- Send JSON with `Content-Type: application/json`. Protected requests send `Authorization: Bearer <accessToken>`.
- Register at `POST /api/v1/registrations` with `{ "email": "customer@example.com", "password": "a-long-password-value" }`. Password policy is at least 12 Unicode characters and at most 72 UTF-8 bytes. Response `201`: `{ "id": 1, "email": "customer@example.com", "createdAt": "..." }`.
- Login at `POST /api/v1/auth/login` with `{ "email": "customer@example.com", "password": "..." }`. Success `200` returns `accessToken`, `tokenType: "Bearer"`, `expiresIn` seconds, and safe `account` fields `id`, `email`, `role`. Current token default lifetime is 900 seconds (configurable, max 3600); algorithm HS256; issuer, audience, signature and expiry are validated. There is no refresh or server-side revocation.
- Registration and login are public. Public catalogue reads are public. `/api/v1/admin/**` requires `ADMIN`; `/api/v1/customers/**` requires `CUSTOMER`, with record ownership derived from JWT subject. Anonymous requests return `401`; wrong roles return `403`.

## Routes

### Public catalogue

| Method and path | Behavior / parameters |
| --- | --- |
| `GET /api/v1/brands` | Paginated active-brand discovery (page defaults 0, size 50; size 1–100). |
| `GET /api/v1/categories?page=0&size=50` | Paginated active-category discovery. |
| `GET /api/v1/products?page=0&size=50&keyword=&brandId=&categoryId=&sort=default` | Paged eligible published products; optional literal substring keyword (max 100), positive IDs, sort `default`, `price_asc`, `price_desc`. Default stable order is name then ID; price ties use ID. Response shape: `{content:[{id,name,slug,description,brandId,brandName,categoryId,categoryName,price,currency:"PKR",availability}],page,size,totalElements,totalPages}`. |
| `GET /api/v1/products/{slug}` | One eligible published product; ineligible/missing is 404. |

Public brand/category list uses corresponding page response DTO. Public products require active brand and category as well as `PUBLISHED` status.

### Admin catalogue management

All routes below require an `ADMIN` bearer token.

| Method and path | Request / behavior |
| --- | --- |
| `POST /api/v1/admin/brands` | `BrandCreateRequest`: name, slug, optional description/logoReference; 201. |
| `GET /api/v1/admin/brands` | All brand statuses. |
| `GET /api/v1/admin/brands/{id}` | One brand. |
| `PUT /api/v1/admin/brands/{id}` | `BrandUpdateRequest`; replaces metadata/status. |
| `PATCH /api/v1/admin/brands/{id}/deactivate` | Soft-deactivate. |
| `POST /api/v1/admin/categories` | `CategoryCreateRequest`: name, slug, optional description; 201. |
| `GET /api/v1/admin/categories?page=0&size=50` | Paged categories across statuses. |
| `GET /api/v1/admin/categories/{id}` | One category. |
| `PUT /api/v1/admin/categories/{id}` | `CategoryUpdateRequest`; replaces metadata/status. |
| `PATCH /api/v1/admin/categories/{id}/deactivate` | Soft-deactivate. |
| `POST /api/v1/admin/products` | `ProductCreateRequest`: name, slug, optional description, brandId, categoryId, price, availability; creates draft. |
| `GET /api/v1/admin/products?page=0&size=50` | Paged products across publication statuses. |
| `GET /api/v1/admin/products/{id}` | One product. |
| `PUT /api/v1/admin/products/{id}` | `ProductUpdateRequest`; replaces product fields, price, availability and relationships. Price is non-negative decimal, max 10 integer and 2 fractional digits. |
| `PATCH /api/v1/admin/products/{id}/publish` | Publish only when referenced brand/category are active. |
| `PATCH /api/v1/admin/products/{id}/unpublish` | Unpublish. |
| `PATCH /api/v1/admin/products/{id}/deactivate` | Soft-deactivate. |

Slug fields are normalized to lowercase hyphen-separated values. Duplicate slugs return 409; invalid fields return 400; absent referenced records return 404; inactive references where prohibited return 409.

### Customer addresses

All routes require a customer token; ownership always comes from the token.

| Method and path | Behavior |
| --- | --- |
| `POST /api/v1/customers/me/addresses` | Create; 201. Required recipientName, phoneNumber, addressLine1, city; optional addressLine2, province, postalCode. |
| `GET /api/v1/customers/me/addresses` | List own addresses. |
| `GET /api/v1/customers/me/addresses/{addressId}` | Read own address. |
| `PUT /api/v1/customers/me/addresses/{addressId}` | Replace all editable fields. |
| `PATCH /api/v1/customers/me/addresses/{addressId}` | Patch a non-empty subset; empty string clears an optional field. |
| `DELETE /api/v1/customers/me/addresses/{addressId}` | Delete own address; 204. |

Example request: `{ "recipientName":"Ayesha Khan", "phoneNumber":"+92 300 1234567", "addressLine1":"House 12, Street 4", "addressLine2":"Gulberg III", "city":"Lahore", "province":"Punjab", "postalCode":"54660" }`. Response fields are those values plus `id`, `createdAt`, and `updatedAt`. Foreign-owned and missing IDs both return 404.

### Customer cart

| Method and path | Behavior |
| --- | --- |
| `GET /api/v1/customers/me/cart` | Get or create the caller's empty persistent cart. |
| `POST /api/v1/customers/me/cart/items` | `{ "productId":42, "quantity":2 }`; add positive 32-bit quantity. 201 for new item, 200 when merged. |
| `PATCH /api/v1/customers/me/cart/items/{itemId}` | `{ "quantity":3 }`; replace quantity. |
| `DELETE /api/v1/customers/me/cart/items/{itemId}` | Remove owned item; 204. |
| `DELETE /api/v1/customers/me/cart/items` | Clear caller's cart; 200 and empty cart response. |

Cart response: `{ "id":6, "items":[{ "itemId":9, "productId":42, "productName":"Linen Shirt", "brandName":"Example Atelier", "unitPrice":1299.95, "quantity":2, "lineSubtotal":2599.90, "available":true }], "subtotal":2599.90, "currency":"PKR" }`. Prices are current display values, not a checkout commitment. Adding requires a published/available product and active brand/category. Existing newly ineligible lines remain visible with `available:false`. No owner or price is accepted from the client.

## Errors and pagination

Errors use `ApiErrorResponse` with `timestamp`, `status`, `error`, `message`, `path`, and `fieldErrors` (each contains `field` and `message`). Validation errors are 400; duplicates/conflicts and unavailable cart products are 409; missing/foreign-owned resources are 404; auth is 401/403. Pagination defaults to page 0 and size 50, with sizes 1–100 where supported; product filters are described above.

## CORS and local configuration

CORS is applied to `/api/**`, permits methods GET/POST/PUT/PATCH/DELETE and headers `Authorization`, `Content-Type`, with credentials disabled and max age 3600 seconds. Set `CORS_ALLOWED_ORIGINS` to an explicit comma-separated list of exact origins (for example `http://localhost:5173`). Wildcard is rejected. Compose now forwards this variable; empty means browser cross-origin requests are not allowed. Local variables: `MYSQL_DATABASE`, `MYSQL_USER`, `MYSQL_PASSWORD`, `MYSQL_ROOT_PASSWORD`, `MYSQL_PORT`, `BACKEND_PORT`, `SERVER_PORT`, `JWT_SECRET_BASE64`, `JWT_ISSUER`, `JWT_AUDIENCE`, `JWT_ACCESS_TOKEN_TTL`, `CORS_ALLOWED_ORIGINS`. Never put secrets into a frontend bundle; only the public API URL and selected origin belong in frontend configuration.
