# Brandista F1.0 — Pilot Scorecard

This is a blank recording template. No pilot, participating brand, live customer, order, or fulfilment result is claimed. Record test activity separately from real activity, and only begin real activity after owner authorization and written partner terms are in place.

## Measurement definitions

| Metric | Definition | Recording method |
| --- | --- | --- |
| Approved participating brands | Count of brands with owner-approved participation terms and active public profile. An F0.9 application approval alone does not qualify. | One row per brand; record agreement approval date and current ACTIVE/INACTIVE catalogue status without publishing confidential agreement content. |
| Published products | Count of products in PUBLISHED state under ACTIVE brands and categories. | Capture admin catalogue count at the start/end of each review window; distinguish AVAILABLE flag from actual stock quantity. |
| Product data accuracy | Sampled fields confirmed against the partner-approved source: name, description, brand/category, price, availability, and authorized images (images are not stored in the current product model). | For each sampled item, record fields checked, pass/fail, checker, date, correction issue ID. Do not infer accuracy from synthetic test fixtures. |
| Successful customer journeys | Count of explicitly defined test journeys that complete all steps available in the build without a blocking defect. For the current app, stop at cart; checkout is unavailable. | Record build/commit, test account label (never password/token), steps, outcome, and whether API calls used mocks, H2, MySQL, or staging. |
| Cart completion during testing | Test sessions that successfully add/update/remove intended items and see backend-calculated totals, divided by test sessions attempting the cart flow. | Report numerator/denominator and environment; do not mix component tests with live API tests. |
| Checkout completion during testing | Not measurable in current software. No checkout endpoint or order creation exists. | Mark N/A until approved implementation exists; never substitute a mock success. |
| Order creation success rate | Valid order creation attempts accepted by a verified order service divided by valid attempts. | N/A today. If implemented later, identify environment and test/real activity separately; no personal or payment data in the scorecard. |
| Order fulfilment success rate | Authorized real orders fulfilled according to written pilot policy divided by authorized real orders due in the period. | N/A today. Only record if owner and participating brand authorize real order activity and define fulfilment. |
| Customer complaints | Count by issue category and severity, plus unresolved count and age. | Use a privacy-safe incident reference and avoid storing unnecessary personal details here. |
| Stock discrepancies | Count of partner-confirmed availability mismatches found after listing/cart interaction. | Record item reference, detection date, mitigation (UNAVAILABLE/unpublished), resolution owner/date. Product availability is only a flag in current software. |
| Brand onboarding time | Elapsed business time from complete intake to verified public activation, excluding partner/owner waiting time where measurable. | Record timestamps and separate operator work from external waiting; report sample size. |
| Partner feedback/unresolved requests | Feedback themes and number of open requests by severity. | Record anonymized theme, owner, status, due date and decision; do not imply requested features are committed. |
