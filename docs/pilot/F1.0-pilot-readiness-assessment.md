# Brandista F1.0 — Pilot Readiness Assessment

Assessment date: 2026-10-14  
Scope: source and report audit plus safe automated checks. No public deployment, external brand contact, real customer/order, payment, or production-data operation was performed.

## Decision

**BLOCKED — not ready for a controlled customer pilot.** Catalogue visibility and cart validations have H2 integration coverage, and the full current backend regression suite passed against isolated H2 (72 tests). Docker/MySQL is unavailable, so no running full-stack customer journey or live database behavior can be verified. Checkout, order creation/history, stock counts/reservations, payment, and fulfilment automation do not exist. Frontend test/lint/build commands cannot start because local npm executables are missing. The F1.0 prompt attachment itself ends mid-sentence in the metrics section; any later acceptance requirements were not available to audit.

No standalone SRS was found in either checked-out repository. The scope below is grounded in the implementation, API contract, F0.6 report, F0.7 report, F0.9 report, and onboarding runbook. Formal SRS conformance remains **BLOCKED**.

## Verified business rules and gaps

- Brand states are `ACTIVE` and `INACTIVE`; an approved F0.9 brand application creates an inactive brand pending separate review/activation.
- Product publication states include draft/published/deactivated; availability is `AVAILABLE` or `UNAVAILABLE`. It is a flag, not inventory count.
- Public product discovery and cart addition require active brand/category and a published product. Detail lookup hides products with an inactive brand/category. Cart responses recalculate display subtotals from current prices and mark now-unavailable products as unavailable.
- Current product model has no image storage, SKU, variants, quantity stock, or merchant account ownership. Public brand DTO includes profile fields and status; public product DTO omits internal publication state and timestamps. No contact/application PII is part of product DTOs.
- Cart ownership is derived from the authenticated principal; integration tests verify another customer cannot change/remove a cart item.
- No order lifecycle, order ownership, item price snapshot, inventory reservation/deduction, idempotency key, checkout, payment, refund, or order history exists.
